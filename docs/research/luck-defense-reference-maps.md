# 운빨 디펜스 참고 맵 역분석

이 문서는 제작 스킬의 지침이 아니다. 두 공개 맵의 배포 파일과 CHK 트리거를 조사한 근거이며, 다른 맵에 그대로 복제할 규칙을 뜻하지 않는다. 트리거 번호는 API 배열의 **0부터 시작하는 인덱스**다. 원본 epScript 소스와 실제 플레이 결과는 확보하지 못했다.

## 조사 자료

| 맵 | 공개 자료 | 크기 / 사람 플레이어 / 트리거 |
| --- | --- | --- |
| [메이플 운빨 디펜스](https://scmscx.com/map/tDdtsjfV) | [맵 정보](https://scmscx.com/api/uiv2/map_info/tDdtsjfV), [CHK](https://scmscx.com/api/chk/json/tDdtsjfV), [해석된 트리거](https://scmscx.com/api/chk/trig/tDdtsjfV) | 256×256 / 4명 / 2,339개 |
| [EUD 개인 운빨 디펜스](https://scmscx.com/map/f4d5zpY4) | [맵 정보](https://scmscx.com/api/uiv2/map_info/f4d5zpY4), [CHK](https://scmscx.com/api/chk/json/f4d5zpY4), [해석된 트리거](https://scmscx.com/api/chk/trig/f4d5zpY4) | 128×96 / 6명 / 1,332개 |

배포 SCX도 내려받았다. 두 아카이브는 사용한 MPQ 리더가 암호화된 항목 읽기를 지원하지 않아 내부 파일 목록을 확인하지 못했다. 따라서 아래 로직은 공개 CHK 해석 결과에 근거한다. 화면 배치는 각 페이지의 미니맵과 CHK 맵 이미지로 확인했다.

## EUD 개인 운빨 디펜스: 확인된 흐름

- 사람 플레이어 6명의 경기장이 3×2로 반복된다. 플레이어 8이 적을 소유하고, `Order` 72개가 적 유닛을 경기장별 위치 사이로 이동시킨다(트리거 1143–1148).
- 슬롯은 P1–P6 사람, P7–P8 컴퓨터다. P7은 무작위 스위치를 설정하는 트리거를 실행하고 P8은 적 유닛을 소유한다. 맵에 미리 배치된 유닛의 소유자는 P7 49개, P8 1개다.
- 뽑기 입력은 시민 유닛을 정해진 위치로 이동시키는 방식이다. 미네랄이 **20 이상**이면 20을 차감하고 플레이어별 사망 카운터를 1 올린다(246–251). 자원이 모자라면 이 트리거는 발동하지 않는다.
- 플레이어 7의 트리거 233이 스위치 0–29를 무작위로 설정한다. 플레이어마다 스위치 5개씩 사용한다. 뽑기 카운터가 있으면 해당 5비트 조합에 따라 플레이어 위치에 유닛 하나를 생성하고 카운터를 1 차감한다(252–413).
- 한 플레이어의 32개 조합 중 **27개**에 유닛 생성 트리거가 있다. 기본 히드라리스크·마린·드라군에 각각 7개, 영웅형 헌터 킬러·짐 레이너·피닉스에 각각 2개를 배정한다. 즉 유닛이 나온 조합만 기준으로 각 기본형은 **7/27**, 각 영웅형은 **2/27**이다. 나머지 5개 조합에는 해당 생성 트리거가 없어 요청 카운터가 남는다. 반복 무작위화로 다음 주기에 처리될 것으로 읽히지만, 실제 게임에서의 시간·체감 확률은 플레이 검증이 필요하다.
- 세 종족은 실제 뽑기 유닛 종류를 나누며, 각 종족에 기본형과 영웅형이 있다. 별도 속성·원소 상성은 이 트리거에서 확인되지 않았다. 뽑힌 유닛은 플레이어별 고정 위치에 `CreateUnitWithProperties`로 생성된다.
- 전역 단계 카운터 1–30에 따라 적 유형 30종이 바뀐다. 플레이어별 카운터가 12에 도달하면 해당 단계 적을 생성하고 생성 횟수를 올린다(1149–1328). 단계 전환 트리거는 1,440 카운트와 90초 타이머, 플레이어별 카운터 초기화를 사용한다(1141–1142). 60회 생성 제한과 80/90 유닛 초과·미션 실패 메시지도 보인다(1074–1110, 1137–1140). 이 수치가 실제 플레이에서 몇 초 간격인지와 80/90의 정확한 판정 대상은 추가 검증이 필요하다.
- 공개 CHK에는 사용자 WAV 슬롯과 `PlayWav` 액션이 보이지 않는다. 명시적인 보스 전용 메시지나 보스 트리거도 확인되지 않았다. 마지막 적인 프로토스 하이 템플러의 사망 카운트가 60에 이르고 적 유닛이 남지 않으면 승리 메시지를 띄운다(1329–1330).

## 메이플 운빨 디펜스: 확인 범위

### 슬롯 크기 기준: 렌더 이미지 측정 (2026-09-30)

[공개 맵 렌더 이미지](https://scmscx.com/api/chk/8424702ec0a3d84286069f159c05226869307ab7d01beb1cd2748dcf44eceaae/map_img)는 8192×8192픽셀이며, 공개 DIM 256×256과 대응하므로 타일당 32픽셀이다. 좌상단 슬롯의 보이는 타일 경계를 기준으로 측정했다. 아래 좌표는 반열린 타일 구간이다.

| 구역 | X / Y 범위 | 외접 크기 |
| --- | --- | --- |
| 밝은 수비 바닥 | `[11, 23)` / `[11, 23)` | 12×12타일 / 384×384픽셀 |
| 적 순환 경로를 포함한 전투 지형 | `[8, 26)` / `[8, 26)` | 18×18타일 / 576×576픽셀 |
| 바깥 어두운 테두리까지 | `[7, 27)` / `[7, 27)` | 20×20타일 / 640×640픽셀 |

수비 바닥과 경로는 모서리가 잘린 형태이므로 외접 사각형 전체가 해당 구역이라는 뜻은 아니다. 소환·관리 오브젝트와 슬롯 사이 여백도 별도다. UNIT의 사람 시작 위치는 `(545,560)`, `(1665,560)`, `(545,1680)`, `(1664,1680)`이며 중심 간격은 약 35타일이다. 이 간격을 플레이 전장의 폭·높이로 사용하면 과대 설계가 된다.

이는 실제 배포 맵의 렌더 이미지와 공개 DIM/UNIT를 대조한 시각적 측정이다. 보호된 MRGN 좌표는 정상 범위가 아니므로 로케이션 범위나 실제 유닛 이동·충돌을 검증한 값으로 해석하지 않는다. 스킬의 크기 기본값은 사용자가 이 맵의 슬롯을 표준으로 지정한 데 따른 것이며, 게임 로직이나 특정 타일 ID를 복원했다는 주장이 아니다.

- 경기장 4개가 맵의 한쪽에 모여 있고 다른 넓은 영역은 장식용 지형이다. 535개 초기 유닛과 73개 스프라이트가 포함된다.
- 슬롯은 P1–P4 사람, P5–P6 비활성, P7–P8 컴퓨터다. 미리 배치된 유닛은 P7 소유 505개, P8 소유 26개다. 보호된 트리거 때문에 각 컴퓨터의 전체 역할을 이 숫자만으로 단정할 수 없다.
- 트리거는 `SetDeaths` 7,572개, `SetSwitch` 404개, `SetResources` 380개, `CreateUnit` 250개 등으로 구성된다. 사망 카운터를 게임 상태로 사용하고 유닛 생성·자원 갱신이 핵심인 것은 확인되지만, 이것만으로 전체 상태 기계를 복원할 수 없다.
- 표시 문자열에서 일반 **50.0%**, 유물 **5.1%**, 서사 **1.0%**, 전설 **0.5%**, 신화 **0.08%**, 태초 **0.019%**라는 개별 획득 안내가 보인다(2116–2327). 드라군·고스트·히드라리스크의 등급별 이름도 보인다. 이는 화면에 쓰인 문구이며, 실제 난수 경로와 전체 확률표를 검증한 값은 아니다.
- 공개 해석 결과에 `Unknown` 액션 3,746개와 `Unknown` 조건 1,396개가 있고, 여러 STRx 인덱스가 범위를 벗어난다. 위치 데이터에도 정상 좌표가 아닌 값이 섞여 있다. 이 때문에 정확한 뽑기·웨이브·보스 로직은 현 단계에서 복원하지 못했다.
- `PlayWav` 액션 53개와 `staredit\\wav\\*.ogg` 등 사용자 소리 경로가 보인다. 음악과 효과음을 구분하거나 재생 시점을 완전히 복원하려면 실행 추적이 필요하다.

## 제작에 적용할 질문

두 맵은 **뽑기 입력 방식, 종족별 유닛군, 실제 확률 구현, 적 경로와 단계, 오디오 사용 여부**가 다르다. 둘 다 컴퓨터 슬롯 2개를 사용하지만, 새 맵에서는 적 소유자 수와 별도 시스템 실행자 필요 여부를 설계에 맞게 확정해야 한다. 이 분석의 수치와 유닛 목록을 새 게임의 기본값으로 자동 채택해서는 안 된다.
